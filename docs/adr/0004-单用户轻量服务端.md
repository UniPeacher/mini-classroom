# 第一版采用自建的单用户轻量服务端

> 实现状态（2026-10-23）：保留服务端 + SQLite 的架构决定。当前只监听本机，没有登录、远程访问或服务端推送；提醒依赖页面保持运行。下文的口令 / Passkey、手机组网和云端迁移属于原始设想，尚未实现，不能据此向公网开放服务。

第一版不做纯前端，而是做一个服务加一个数据库。服务端负责存储学习数据、在后台生成候选池、按提醒时段定时推送，并代为调用 AI。原因是以下几个已定需求都离不开服务端：多设备学习需要数据同步；候选池需要在用户关闭页面后继续生成；网页推送需要服务端按时发出；AI 密钥不能出现在浏览器里。登录只服务一个用户，用一个口令或 Passkey 即可，不做注册体系。部署分两步：测试期跑在用户自己的 Mac 上，以便直接访问本机的模型代理，手机通过同一 Wi-Fi 或 Tailscale 之类的组网工具访问；核心循环稳定、换成云端可访问的模型 API 后，再迁到云上。Mac 开合盖时间不定，所以后台任务必须能中断后续跑；提醒时段内如果 Mac 处于休眠，提醒就漏掉，不补发。具体技术栈另行决定。

## Considered Options

- 纯本地（数据存浏览器，前端直连 AI）：多设备同步、后台生成、定时推送都做不到。
- 后端即服务平台（Supabase、Firebase 等）：只省掉单用户下本来就简单的存储和登录，后台生成和定时任务仍要另写云函数，还多了一个外部平台的约束。
