# 模型层与供应商解耦

> 实现状态（2026-10-23）：文本任务共用一个可配置模型，另有可选的图像生成模型；配置可在设置页保存到本机数据库，环境变量作为未保存时的默认值。下文的图片输入能力配置尚未实现。当前接口与配置项见 [开发指南](../development.md)。

系统通过一个统一的模型接口调用 AI，可以接入 OpenAI、Anthropic、Gemini 等格式的服务（包括 OpenAI 兼容的本地代理）；用哪个供应商、哪个模型由配置决定，业务代码不感知具体供应商。为此有三条约束：

1. 业务功能不依赖某个供应商独有的能力。提示词缓存、批量接口这类能力只作为可选的成本优化，没有它们功能照常运行。
2. 模型的能力差异写在配置里（是否支持图片输入、推理强度等），不在业务代码里按供应商分支判断。
3. 候选池里的结构化内容（题目、参考答案、形式、预估时长等）一律按模式校验；校验失败就重试，重试仍失败就丢弃，不让格式错误的内容进入候选池。

第一版只配一个模型，所有用途共用；等到真需要按用途分工（比如批改换用更便宜的模型）时，再加上按用途指定模型的配置。API 密钥只放在环境变量或不纳入版本管理的本地配置里，不写进代码和文档。

## Considered Options

- 绑定单一供应商的原生 SDK：能直接用上该供应商的独有能力，但换模型就要改业务代码，而且用户当前的测试环境是 OpenAI 兼容的本地代理。
