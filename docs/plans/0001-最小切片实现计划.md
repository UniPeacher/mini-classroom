# 切片 1：从输入主题到第二节微课堂

## 目标与验收

打通一条真实路径：

> 输入"TypeScript 常用技能" → AI 生成骨架知识图谱 → 第 1 节微课堂（文字讲解 + 选择题 + 简答）→ 选择题按规则判分、简答由 AI 批改，答对后自评 → FSRS 更新记忆状态 → 后台补满候选池 → 第 2 节微课堂

**验收场景**（同时写成自动化测试和人工走查）：

1. 新建主题后，图谱中有 15~30 个知识点及其前置关系，第 1 节在图谱生成完成后自动备好。
2. 第 1 节包含若干新知识点。假设你把"unknown 类型收窄"的简答答错，而把"联合类型"的选择题答对并自评"良好"。
3. 结束第 1 节，再把时钟拨到第二天（开发模式），打开第 2 节：
   - 打开时不调用 AI（全部内容从候选池取），响应时间小于 200ms；
   - 包含"unknown 类型收窄"的复习，且它的形式与上次不同（比如上次是简答，这次是选择题）；
   - "联合类型"的下次到期时间按 FSRS 计算，第二天还不到期，所以不出现；
   - 至少有 1 个新知识点。

## 不在本切片内

摸底诊断（本切片中所有知识点从"未学"开始）、应用和保持两个阶段的形式、拆解、联结练习、图解与动画、认知地图、提醒、手机适配、申诉、导出与速查表、登录（只监听本机）。掌握阶段的状态机先只实现"未学 → 理解 → 回忆"以及答错退回。

## 目录结构

单个包，不拆 monorepo；内容结构的 Zod 定义放在 `src/shared/`，前后端共用。

```
src/
  shared/        Zod 内容结构（知识图谱、讲解、选择题、简答、批改结果）与领域类型
  domain/        纯函数，不碰 IO：掌握阶段状态机、评分映射、认知边缘、组装规则
  ai/            模型网关（按配置接入供应商）、各生成器与批改器（校验 + 重试）
  store/         SQLite 表定义、迁移、读写
  jobs/          持久化任务队列与后台 worker（启动时续跑未完成任务）
  server/        Hono 路由
  web/           React 页面
tests/           领域单测、AI 契约测试、端到端验收测试
```

## 领域核心（纯函数，重点测试）

**掌握阶段状态机**（本切片部分）：

- 未学 → 理解：讲解被展示时。
- 理解中，当场小题答对 → 进入回忆，开始 FSRS 调度；答错 → 仍是理解，下次换一种讲解形式重讲。
- 回忆中答错 → 留在回忆，FSRS 记为"忘了"，间隔变短，下次换形式。

**评分映射**：判错 → Again；答对后自评"困难 / 良好 / 轻松" → Hard / Good / Easy。

**错误类型**：选择题的每个干扰项在出题时就标注它对应的误解（来自易混关系），选中这类干扰项就判为误解，否则为遗忘；简答由 AI 批改时给出错误类型。本切片只记录错误类型，不触发对比教学或拆解。

**认知边缘**：前置知识点全部已进入回忆阶段（或没有前置）的未学知识点。

**组装规则** `assemble(states, pool, now, budget)`：

1. 取已到期的复习，按 FSRS 的可提取性从低到高排（最容易忘的在前），依次放入，直到占满预算；
2. 剩余预算放推进项（理解阶段的重讲）；
3. 再放新知识点（讲解 + 当场小题），保底 1 个；如果到期复习的总时长超过 3 节的预算，就不放新知识点；
4. 三类内容穿插排列，同一新知识点的讲解必须排在它的小题前面；
5. 同一知识点不选与 `last_form` 相同的形式。

## AI 层

- **模型网关**：按 `.env` 构建模型，业务只调用 `generateStructured(schema, prompt)`。
- **生成器**：骨架图谱、讲解（文字）、选择题（含参考答案和干扰项的误解标注）、简答（含参考答案）。
- **批改器**：简答批改，输出对 / 部分对 / 错、错误类型和解释。
- **校验与重试**：输出不符合 Zod 结构时最多重试 2 次；仍失败就丢弃这一项，并在任务里记录错误。

## 后台任务

- `generate_graph`：新建主题后执行，完成后紧接着入队 `fill_pool`。
- `fill_pool`：每节结束后执行。目标是候选池里常备约两节的量：未来 48 小时内会到期的复习，每个知识点备一项与上次形式不同的内容；认知边缘上排在前面的新知识点，各备讲解和小题。
- Worker 在服务进程内轮询 `jobs` 表；服务启动时把 `running` 状态的任务重置为 `pending`，接着执行，用来应对 Mac 合盖后进程被挂起的情况。

## 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/topics` | 新建主题，入队图谱生成 |
| GET | `/api/topics/:id` | 主题和图谱的生成状态 |
| POST | `/api/sessions/next` | 组装并开始下一节（只读候选池，不调 AI） |
| POST | `/api/attempts` | 提交作答，返回判定结果；简答这一步会同步调用 AI 批改 |
| POST | `/api/attempts/:id/rating` | 提交自评，更新记忆状态 |
| POST | `/api/sessions/:id/finish` | 结束本节，入队补满候选池 |

开发模式下支持请求头 `X-Dev-Now`，用来覆盖"当前时间"，以便验收"第二天"。

## 前端（本切片只做最简单的页面）

1. 新建主题页：输入主题，然后等待图谱生成。
2. 学习页：逐项展示讲解、选择题、简答 → 显示批改结果和参考答案 → 答对后自评 → 下一项。
3. 结束页：本节小结，以及"下一节已备好 / 还在准备中"的提示。

## 测试

- **领域单测**：按业务定义设计用例，覆盖状态机每条转移、评分映射、认知边缘，以及组装规则的五条规则（含复习积压时暂停新学、新学保底、形式不重复）。
- **AI 契约测试**：用 AI SDK 提供的 Mock 模型，覆盖结构合法、第一次结构非法后重试成功、连续非法后丢弃三种情况。
- **端到端验收测试**：用 Mock 模型和固定时钟跑完整的验收场景，并断言第 2 节组装期间 AI 被调用 0 次。
- **真机冒烟**：一个手动脚本，连本机代理生成一张真实图谱和一节课，由你人工检查内容质量。
