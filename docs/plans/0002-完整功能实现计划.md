# 完整功能实现计划

切片 1 打通了"新建主题 → 两节微课堂"的核心循环。本计划把术语表（CONTEXT.md）和 ADR 中第一版范围内的其余功能全部实现，并按 design-taste-frontend 的 app 界面规范重做前端。分享链接、卡片、复刻、竞赛属于第二期，不在本计划内。

## 实现时的决策

需求文档没有写死、实现时必须定下的规则，取值如下，均可在设置中调整或后续再议：

| 事项 | 规则 |
|---|---|
| 回忆 → 应用 | 回忆阶段答对后，记忆稳定性达到 7 天 |
| 应用 → 保持 | 应用阶段答对后，记忆稳定性达到 30 天 |
| 应用、保持阶段答错 | 退回回忆，间隔按 FSRS 缩短 |
| 拆解触发 | 理解或回忆阶段连续答错 3 次 |
| 对比教学触发 | 答错且错误类型为误解，下一次讲解或复习改用对比讲解 |
| 摸底直接答对 | 进入回忆阶段，按"轻松"建卡，约两三周后到期再验证 |
| 推断掌握 | 新增"推断掌握"状态，视同学过；每节最多抽查 2 个，答对进入回忆，答错从理解开始教 |
| 联结练习的对象 | 优先已学会的前置知识点，其次已学会的易混知识点，再次用户的已有知识；都没有就不出 |
| 错误联结 | 不入图，对方知识点立即到期复习 |
| 新学轮换 | 每节的新知识点只来自一个主题：在有可学内容的进行中主题里，选"已供给新学的节数 ÷ 优先级"最小的 |
| 主题回访 | 每 14 天一次，在一节结束时出现 |
| 提醒 | 浏览器通知，页面开着时生效（本机运行没有推送服务器）；某时段前 60 分钟内已完成一节则跳过 |
| 时长校准 | 按最近 20 次作答的"实际用时 ÷ 预估用时"中位数，限制在 0.5~2 倍 |
| 申诉 | 只能对这个知识点最近一次计入的作答申诉；改判时先还原作答前的记忆状态 |

## 形式

| 形式 | 用于 | 手机 | 判分 |
|---|---|---|---|
| 直接讲解、类比讲解、反例讲解、图解、分步揭示、预测揭晓、对比讲解 | 理解（对比讲解由误解触发） | 是 | — |
| 选择题 | 理解小题、回忆、保持；核心检验（回忆） | 是 | 规则 |
| 简答 | 理解小题、回忆、保持 | 是 | AI |
| 点选错误行 | 回忆、应用、保持 | 是 | 规则 |
| 补全 | 应用、保持 | 否 | AI |
| 修正 | 应用、保持；核心检验（应用） | 否 | AI |

## 步骤（一步一提交）

1. 设置存入数据库，提供读写接口。
2. 新形式：内容结构、生成提示词、判分。
3. 四个掌握阶段的推进、各阶段形式池、形式偏好、手机只出适合手机的形式。
4. 多主题：暂停与恢复、优先级、新学按主题轮换、暂停主题照常复习、主题回访。
5. 错误类型的后果：对比教学、拆解。
6. 申诉。
7. 摸底诊断、推断掌握、已有知识。
8. 联结练习与联结。
9. 认知地图：一张图覆盖所有主题，组块、认知边缘、迷雾、联结、已有知识。
10. 时长校准。
11. 提醒时段与每日节数上限。
12. 速查表与 Markdown 导出。
13. 模型供应商接入 Anthropic、Gemini。
14. 前端按 app 界面规范重做，加 PWA。
